# Feature Specification: ブログ作成内容の保存

**Feature Branch**: `001-save-tiptap-content`  
**Created**: 2025-12-31  
**Status**: Draft  
**Input**: User description: "/blogs/newに表示されているtiptapエディタに入力されたテキスト情報、画像などを保存できるようにしたいです。保存先はsuperbaseです。"

## Clarifications

### Session 2025-12-31

- Q: `/blogs/new`の下書きはユーザーごとに何件保持するか？ → A: ユーザーごとに1件のみ
- Q: 保存済み画像の扱いはどうするか？ → A: 画像は最新の参照に追従する
- Q: 画像参照が失われた場合の復元挙動は？ → A: 画像を非表示にする
- Q: 同時保存の扱いはどうするか？ → A: 同時保存は起きない前提
- Q: 保存失敗時の挙動はどうするか？ → A: 編集内容を保持し手動再試行

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 下書きを保存する (Priority: P1)

ブログ作成者が`/blogs/new`のエディタで入力した内容（本文・見出し・画像など）を明示的に保存し、後から同じ内容を復元できる。

**Why this priority**: 作成中の内容を失わず継続編集できることが最も重要な価値だから。

**Independent Test**: `/blogs/new`で内容を入力して保存し、再読み込み後に同じ内容が表示されることで確認できる。

**Acceptance Scenarios**:

1. **Given** 作成者が本文と画像を入力済みの状態、**When** 保存操作を実行する、**Then** 保存成功のフィードバックが表示される
2. **Given** 保存済みの下書きがある状態、**When** `/blogs/new`を再訪する、**Then** 保存した内容が復元されている

---

### User Story 2 - 保存失敗時に再試行できる (Priority: P2)

保存処理が失敗した場合でも、作成者が原因を把握でき、同じ内容を失わず再試行できる。

**Why this priority**: 失敗時のデータ損失を防ぎ、作成体験の信頼性を担保するため。

**Independent Test**: 保存時に失敗が発生した場合、エラーメッセージが表示され、同じ内容で再度保存できることを確認できる。

**Acceptance Scenarios**:

1. **Given** 保存に失敗する状況、**When** 保存操作を実行する、**Then** 失敗理由が分かるエラーメッセージが表示される
2. **Given** 失敗後も編集内容が保持されている状態、**When** 再度保存する、**Then** 正常に保存できる

---

### User Story 3 - 画像が正しく復元される (Priority: P3)

保存した画像が本文内の位置や順序を保ったまま復元され、視覚的な構成が崩れない。

**Why this priority**: 画像の崩れは記事品質に直結するため、復元の正確性が重要。

**Independent Test**: 画像を含む本文を保存し、再読み込み後に画像の位置と順序が一致することを確認できる。

**Acceptance Scenarios**:

1. **Given** 本文中に複数の画像が挿入された状態、**When** 保存して再読み込みする、**Then** 画像の順序と位置が保存前と一致する

---

### Edge Cases

- 画像サイズが大きい場合でも保存できるか？
- 本文が空の状態で保存した場合はどうなるか？
- 通信障害で保存に失敗した場合の挙動は？
- 既存の下書きがある状態で保存した場合はどうなるか？
- 画像が差し替え・削除された場合に本文表示がどうなるか？
- 画像参照が失われた場合に本文から画像が取り除かれるか？

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: System MUST `blogs/new`で入力された本文の内容を保存できる
- **FR-002**: System MUST 本文内に挿入された画像を保存し、本文内の位置情報と関連付ける
- **FR-003**: Users MUST 保存操作を明示的に実行できる
- **FR-004**: System MUST 保存済み内容を再訪時に復元できる
- **FR-005**: System MUST 保存成功・失敗の状態をユーザーに明確に表示する
- **FR-006**: System MUST 保存失敗時でも編集内容を保持し、再試行できる
- **FR-007**: System MUST ユーザーごとに1件の下書きを保持し、保存時は既存下書きを更新する
- **FR-008**: System MUST 画像参照が更新された場合、復元時に最新の画像を表示する
- **FR-009**: System MUST 画像参照が失われた場合、復元時に本文から該当画像を非表示にする
- **FR-010**: System MUST 保存失敗時に自動再試行は行わず、手動再試行を提供する

### Key Entities *(include if feature involves data)*

- **Draft**: 作成中のブログ記事の下書き。本文、画像参照、更新日時を含み、ユーザーごとに1件のみ保持される
- **MediaAsset**: 記事内で使用される画像。画像を識別するための情報、表示順序、関連する下書きを含み、参照先が更新された場合は最新画像が表示される

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 保存操作から5秒以内に成功/失敗のフィードバックが表示される
- **SC-002**: 再読み込み後、本文と画像の復元一致率が100%である
- **SC-003**: テスト参加者の90%が初回操作で保存を完了できる
- **SC-004**: 保存失敗時の再試行で95%が内容を失わずに完了できる

## Assumptions

- ブログ作成は認証済みユーザーが行う
- 保存対象は`/blogs/new`で入力された下書きのみで、公開や一覧表示は本スコープ外
- 同一ユーザーによる同時保存は発生しない

## Dependencies

- 既存のユーザー認証が利用可能である
- 画像ファイルを保存・取得できる基盤が利用可能である
